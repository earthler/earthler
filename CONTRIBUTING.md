# Contributing

Earthler is at the design stage and has no published code yet. For now, the most useful contribution is to point out errors or unclear passages in what is already written and to share the experience of people who live in or organize communities. English is the working language of this repository, and all participation follows the [code of conduct](CODE_OF_CONDUCT.md).

The project makes no promise of individual support or of a response time. Every proposal is read as a contribution, and what enters the repository is decided as described in [GOVERNANCE.md](GOVERNANCE.md).

## Issues

Before opening an issue, check whether the subject has already been covered. There are two forms: Correction, for something wrong in what has been published, and Proposal, for an idea or experience that could improve the project. Security problems never go in a public issue and follow the path described in [SECURITY.md](SECURITY.md).

## Pull requests

A small fix can go straight to a pull request. For a larger change, open an issue first, so nobody loses work on something that will not be accepted. Every change needs the approval of a person before it enters, no matter who proposes it. The files in `brand/` do not accept changes through contributions.

## Signing your commits

The project uses the [Developer Certificate of Origin](DCO), and each commit needs a `Signed-off-by` line with the contributor's name and email. With that line, you declare that you have the right to submit the work under the project's license. To sign, use the `-s` option:

```bash
git commit -s -m "Fix the license link in the README"
```

An automated check looks for this line on every pull request. If you forgot to sign your last commit, run `git commit --amend -s --no-edit` and push again with `git push --force-with-lease`.

The name and email in a commit stay public in the history forever. If you prefer not to expose your address, use the `noreply` email that GitHub offers in your account settings.

## Licensing of contributions

Every contribution enters under the project's license, the [GNU AGPL v3.0 or later](LICENSE). There is no copyright assignment: you remain the owner of what you wrote, and nobody gains the power to change the license of your contributions without your consent.

## Use of artificial intelligence

Contributions made with the help of AI are welcome and follow the same rules. Whoever signs the commit answers for everything they submit, must have read and understood it, and must have the right to submit it. Text or code that is generated and submitted without review will be declined.
